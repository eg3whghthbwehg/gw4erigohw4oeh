What this is

A mod menu for a browser-based GTA V port, plus the tooling that makes it possible. The port itself is not mine — it is an archived build. What is here is the menu, the engine bridge, and the build tooling.

Wall ESP

Boxes and distance labels on peds and vehicles, drawn on a canvas above the game so they show through walls.

Fly / noclip

Per-frame movement on the engine thread with the menu's input isolated from the game's.

TV crash guard

A wasm patch that stops the video player taking the tab down when you change channel.

Saved loadout

Toggles persist to localStorage and re-apply once the engine reaches a frame.

The engine bridge

Scripts can't touch the engine directly, so the port's game.wasm is patched to poll a mailbox in shared memory once per frame. The page writes a command into a slot; the engine runs it on the engine thread and writes the result back. That gives the menu ~195 real engine calls with no patching of individual scripts.

CTheScripts::Process()   <-  call __gta_poll()   (injected as the first instruction)

__gta_poll():
    if (!mailbox) { mailbox = calloc(1, 8192); publish_address(); }
    heartbeat++
    for slot in 0..32:
        if (cmd = slot.cmd) { dispatch(cmd, slot); if (!slot.sticky) slot.cmd = 0 }
ParameterValueWhy

Slots12 one-shot, 20 stickyone-shot = run once, sticky = every frame

Four things that cost real time

Never guess an entity handle

Entity handles look like (pool << 14) | index, so brute-forcing them to enumerate the world is tempting. It freezes the engine permanently: a stale pool slot wedges the thread inside the entity lookup and the heartbeat stops dead. A reload is the only way out.

The fix was to stop guessing. GetClosestPed and GetClosestVehicle resolve the pool inside the game and hand back a live handle. Discovery samples rings around the player and asks the game what's nearest each point. Nothing here can wedge the thread.

Every mailbox call costs exactly one frame

Measured at 16.0 ms per call against a 60 fps engine — that's latency, not work. The command itself is microseconds; the poller only runs once per frame. So throughput is bounded by concurrency, not speed: twelve calls in flight is twelve calls per frame. A naive 436-call scan looked like 17.7 s and dropped the game to 3 fps; the same scan at 90 calls with 12 workers runs in 250 ms at a steady 63 fps.

The port ships a TV with no videos

TVPlaylists.xml is present and lists every channel. No video archive exists anywhere in the data tree — verified by checking all 5,814 manifest entries, not by spot checks. Changing channel hands rage::bwMovie a file that isn't there, and the tab traps.

The patch gates SetMovieSync, Play and AsyncBink behind one byte in the mailbox header. Guard on, the player is skipped and the TV stays dark instead of dying. Toggle it in the menu and watch the byte move.

The corner minimap needs a thread that isn't running

The pause-menu map works. The corner radar doesn't. Both read the same map tiles, both verified present and byte-exact against the manifest — so it isn't data.

The radar draws through CMiniMap_RenderThread, a dedicated render thread this web build never runs. Calling Render() from the engine thread doesn't crash: it deadlocks. Heartbeat froze at 1113 and never ticked again. There's no switch, native, or menu option that brings it back — it needs the render thread implemented in the wasm.

On the missing video archives. This is a data-completeness gap in the build, not a bug in the menu. With the archives present, the guard can be switched off and the TV works normally. It cannot be fixed from the page.

Tooling

Four Python files, standard library only. patch_wasm.py injects the poller, gates the movie player, and writes bridge.json; wasm_tools.py parses the name section so commands can be referenced by demangled C++ name instead of index.

python patch_wasm.py game.wasm.orig game.wasm bridge.json
# commands: 195 poll func idx 91111 global idx 57 hook 63788
# orig 63201802 -> 63206094 bytes
bridge_spec.py

195 commands as (js key, exact demangled name). Duplicates are a hard error — a repeated key silently collapses in the JSON dict and sends callers to the wrong command id.

patch_wasm.py

Appends the poller, injects call __gta_poll into CTheScripts::Process, and gates the movie player.

patch_js.py

Patches the address relay in game.js and index.html.

wasm_tools.py

Name-section parser and function-signature reader.

Requirements

WebGPU, WebAssembly with memory64 and shared memory, and Cross-Origin-Opener-Policy: same-origin plus Cross-Origin-Embedder-Policy: require-corp for SharedArrayBuffer. Chrome or Edge. Needs byte-range requests — static hosting without range support will not stream the archives.

Menu, bridge and tooling written for this project. GTA V and its assets are Rockstar Games' property; this site hosts none of them. Port build 8b0b5899ed.
